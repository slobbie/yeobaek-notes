# 커밋과 풀 리퀘스트 컨벤션

## 목적

커밋 메시지와 풀 리퀘스트는 함께 신뢰할 수 있는 의사결정 기록을 이룬다.

- 커밋 메시지는 되돌릴 수 있는 작업 단위의 이유, 내용, 검증 결과를 남긴다.
- 풀 리퀘스트는 포함된 커밋을 바탕으로 전체 변경의 배경, 범위, 영향, 위험과 최종 검증 결과를 남긴다.
- 두 기록의 이유, 범위 또는 검증 결과가 다르면 병합하지 않는다. 사실에 맞게 커밋 메시지와 풀 리퀘스트를 먼저 정정한다.

## 커밋 컨벤션

`type(scope): subject` 형식을 사용한다. `type`과 `scope`는 도구 호환을 위해 영문 식별자를 사용하고, `subject`는 한국어로 작성한다.

허용 scope는 `blog`, `admin`, `content`, `seo`, `analytics`, `ui`, `db`, `repo`다.

| Type | 사용 시점 |
| --- | --- |
| `feat` | 사용자에게 보이는 기능 추가 |
| `fix` | 동작 오류 또는 회귀 수정 |
| `refactor` | 의도한 동작 변화 없는 내부 구조 개선 |
| `perf` | 측정 가능한 성능 개선 |
| `test` | 테스트만 변경 |
| `docs` | 문서만 변경 |
| `chore` | 제품 동작과 무관한 유지보수 |
| `ci` | CI 또는 워크플로 변경 |
| `build` | 빌드 도구 또는 의존성 변경 |

커밋 하나에는 하나의 목적만 담는다. subject는 마침표 없이 한국어 명령형으로 작성한다. 제목만 있는 커밋은 허용하지 않으며, 모든 커밋 본문에 아래 항목을 작성한다.

```text
변경 이유:
- 이 작업이 필요한 이유와 결정 배경

변경 내용:
- 이 커밋에 포함한 변경
- 의도적으로 포함하지 않은 범위가 있다면 함께 기록

검증 결과:
- 실행한 명령과 결과
- 실행하지 못한 검증은 미실행 사유
```

본문은 파일 목록을 반복하는 대신 코드만으로 알 수 없는 결정과 검증 근거를 설명한다. 확인하지 않은 내용을 성공으로 기록하지 않는다.

예시:

```text
feat(blog): 글 검색 기능을 추가한다

변경 이유:
- 글이 늘어나도 원하는 기록을 제목과 내용으로 찾을 수 있어야 한다.

변경 내용:
- 공개 글의 제목, 요약, 본문을 대상으로 검색한다.
- 검색어 원문은 분석 정보에 포함하지 않는다.

검증 결과:
- npm test: 전체 테스트 통과
```

## 브랜치와 병합 흐름

기준 브랜치는 `develop`이다. 모든 작업은 최신 `develop`에서 분기하고, PR을 통해 `develop`으로 병합한다.

```text
develop → 작업 브랜치 → 커밋 → PR (base: develop) → 검토·검증 → develop 병합
```

- 브랜치 이름은 `type/짧은-작업명`으로 쓴다. 예: `feat/post-search`, `docs/geo-convention`.
- 하나의 브랜치는 하나의 사용자·제품 목적만 다룬다. 다음 목적은 병합 뒤 새 브랜치에서 시작한다.
- PR을 열기 전 최신 `develop` 기준으로 충돌을 해결하고, PR의 검증 근거를 최신 상태로 갱신한다.
- PR 병합 상태를 확인한 뒤 완료된 작업 브랜치를 로컬과 원격에서 삭제한다. 병합되지 않았거나 확인되지 않은 브랜치는 삭제하지 않는다.
- `main`에는 배포 가능한 통합 결과만 병합한다. 공개 배포가 시작되기 전에는 `develop`을 통합 기준으로 유지한다.

## 풀 리퀘스트 컨벤션

- PR 제목은 커밋 컨벤션을 따른다. 제목 설명과 본문은 한국어로 작성한다.
- PR은 개별 커밋의 이유·범위·검증 결과를 누락하거나 다르게 요약하지 않는다.
- 템플릿의 모든 항목을 채운다. 해당하지 않으면 `없음`, 알 수 없으면 `확인 필요`라고 쓴다.
- 확인 가능한 사실만 쓴다. 추측 대신 결정 문서나 한계를 남긴다.
- PR 하나는 하나의 제품 결과에 집중한다. 후속 작업은 현재 범위 밖 항목에 남긴다.
- 머지 전에 리베이스 또는 충돌 해결을 마친다. 필수 검증이 실패한 상태로 머지하지 않는다.

## 검토 기준

검토자는 코드, 커밋 메시지, PR 문서를 서로 대조해 다음 순서로 확인한다.

1. 문제와 의도한 결과.
2. 포함·제외 범위.
3. 동작, 데이터, 보안, SEO, 분석, 접근성 영향.
4. 실행한 명령과 결과.
5. 위험, 되돌리기 방법, 미해결 질문.
6. 커밋 메시지와 PR의 결정·범위·검증 결과가 일치하는지.
