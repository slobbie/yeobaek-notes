# 남은 작업 실행 계획

## 목적

이 문서는 공개 블로그와 로컬 관리자의 화면 확정 이후 남은 백엔드, 통합 검증, 공개 배포 작업을 실행 가능한 단위로 나눈다. 작업의 순서와 상태는 `docs/implementation-plan.md`에서 관리하고, 각 작업의 세부 범위와 검증 기준은 이 문서에서 관리한다.

## 변하지 않는 운영 경계

- Vercel에는 `apps/web` 공개 블로그만 배포한다.
- `apps/admin`은 `127.0.0.1`에서만 실행하며 배포하지 않는다.
- `service_role` 키는 로컬 관리자 서버에서만 사용하고 브라우저와 공개 번들에 넣지 않는다.
- 공개 웹은 RLS가 허용한 발행 콘텐츠만 읽는다.
- 화면 컴포넌트는 Supabase를 직접 호출하지 않고 저장소 함수를 통해 데이터를 받는다.
- 분석에는 이름, 이메일, 원문 검색어, IP 주소, 사용자·기기 식별자, 본문 자유 입력값을 저장하지 않는다.
- 각 작업은 `develop`에서 분기하고 사용자 확인 뒤 상세 커밋과 PR을 작성한다.

## B-01 콘텐츠·출처·분석 스키마와 RLS

### 목표

콘텐츠와 분석 데이터의 저장 구조를 마이그레이션으로 재현하고 공개 읽기와 관리자 쓰기의 경계를 데이터베이스에서 강제한다.

### 태스크

- [ ] B-01-01 Supabase CLI와 로컬 실행 조건을 확인하고 저장소에 필요한 설정만 추가한다.
- [ ] B-01-02 현재 `packages/content` 계약을 기준으로 `posts` 테이블과 제약 조건을 정의한다.
- [ ] B-01-03 글별 출처와 표시 순서를 보존하는 `post_sources` 테이블을 정의한다.
- [ ] B-01-04 현재 분석 이벤트 계약과 보존 정책을 반영한 `analytics_events` 최소 구조를 정의한다.
- [ ] B-01-05 생성일·수정일 자동 기록과 최초 발행일 유지 규칙을 함수와 트리거로 정의한다.
- [ ] B-01-06 slug 고유성, 상태, 분야, 날짜 순서, 출처 주소 등 데이터 제약을 정의한다.
- [ ] B-01-07 발행 글과 연결된 출처만 공개 읽기를 허용하는 RLS 정책을 정의한다.
- [ ] B-01-08 공개 역할의 콘텐츠 쓰기와 분석 데이터 직접 접근을 차단한다.
- [ ] B-01-09 빈 DB에서 마이그레이션을 다시 실행하고 공개 역할과 관리자 역할의 허용·차단 결과를 검증한다.
- [ ] B-01-10 테이블, 컬럼, 관계, 정책, 날짜 규칙을 `docs/database-design.md`에 기록한다.

### 산출물

- Supabase 로컬 설정
- 순서가 보장된 SQL 마이그레이션
- RLS와 날짜 동작 검증 자료
- `docs/database-design.md`
- 실제 값을 포함하지 않는 환경 변수 예시

### 완료 조건

- 빈 로컬 DB를 한 명령으로 재구성할 수 있다.
- 공개 역할은 발행된 글과 그 글의 출처만 읽을 수 있다.
- 공개 역할은 초안을 읽거나 콘텐츠를 추가·수정·삭제할 수 없다.
- 분석 테이블은 B-04 수집 경로가 완성되기 전까지 외부에서 읽거나 쓸 수 없다.
- 최초 발행 뒤 글을 수정해도 발행일은 유지되고 수정일만 갱신된다.

### 포함하지 않는 범위

- 공개 화면의 Supabase 연결
- 관리자 저장·발행 버튼 연결
- 분석 이벤트 수집 API와 지표 화면
- 운영 Supabase 프로젝트 변경

## B-02 공개 웹 읽기 저장소

### 목표

공개 블로그가 fixture 대신 Supabase의 발행 콘텐츠를 읽되 기존 화면, 검색 정보, RSS와 사이트맵의 계약을 유지한다.

### 태스크

- [ ] B-02-01 공개용 Supabase 환경 변수와 서버 전용 클라이언트 경계를 정의한다.
- [ ] B-02-02 목록, slug 상세 조회, 최신순 조회를 제공하는 콘텐츠 저장소 함수를 구현한다.
- [ ] B-02-03 DB 행을 현재 공개 콘텐츠 계약으로 변환하고 잘못된 데이터는 공개하지 않는다.
- [ ] B-02-04 홈, 글 모아보기, 상세 페이지를 저장소 함수에 연결한다.
- [ ] B-02-05 canonical, Open Graph, JSON-LD, sitemap, RSS가 같은 발행 데이터를 사용하도록 연결한다.
- [ ] B-02-06 실데이터가 늘어날 때의 캐시와 갱신 방식을 결정하고 검증한다.
- [ ] B-02-07 운영 실행 경로에서 fixture 의존을 제거하고 테스트 자료로만 남긴다.
- [ ] B-02-08 DB 오류와 존재하지 않는 글에서 공개할 화면과 로그 범위를 검증한다.

### 완료 조건

- 공개 앱은 `published` 상태의 글만 최신순으로 보여준다.
- 목록, 상세, 검색 메타데이터, 구조화 데이터, sitemap, RSS가 같은 데이터를 사용한다.
- DB에 없는 slug는 404로 처리된다.
- `service_role` 키와 관리자 코드가 공개 번들에 포함되지 않는다.
- 공개 앱 빌드와 기존 사용자 동작 테스트가 통과한다.

### 포함하지 않는 범위

- 콘텐츠 쓰기
- 관리자 기능
- 분석 이벤트 저장

## B-03 로컬 관리자 쓰기 저장소

### 목표

로컬 관리자에서 초안을 저장하고, 발행 전 검사를 통과한 글을 발행하며, 기존 글을 수정할 수 있게 한다.

### 태스크

- [ ] B-03-01 로컬 관리자 서버에서만 `service_role` 키를 읽는 환경 변수 경계를 구성한다.
- [ ] B-03-02 글 목록·상세·생성·수정 저장소 함수를 관리자 데이터 경계에 구현한다.
- [ ] B-03-03 편집 화면에 새 글과 기존 글 불러오기를 연결한다.
- [ ] B-03-04 초안 저장은 발행일을 만들지 않고 생성일·수정일을 DB가 기록하도록 한다.
- [ ] B-03-05 발행 전 검사 오류가 없을 때만 발행하고 최초 발행일은 DB가 기록하도록 한다.
- [ ] B-03-06 발행 글 수정 시 발행일을 유지하고 수정일만 갱신하는 것을 확인한다.
- [ ] B-03-07 중복 slug, 저장 실패, 연결 실패를 한국어로 설명하고 입력 내용을 잃지 않게 한다.
- [ ] B-03-08 관리자 코드, 쓰기 API, 비밀 키가 공개 빌드에 포함되지 않는 회귀 검사를 추가한다.
- [ ] B-03-09 이미지 운영 방식을 결정한다. 외부 URL을 유지할지 Supabase Storage 업로드를 추가할지 별도 확인받는다.

### 완료 조건

- 초안 저장, 최초 발행, 발행 글 수정이 로컬 관리자에서 동작한다.
- 발행·수정 날짜를 사용자가 직접 입력하지 않는다.
- 관리자 비밀 키는 서버 경계 밖으로 전달되지 않는다.
- 저장 실패 후에도 작성 중인 내용이 화면에 남는다.
- 공개 블로그에서 새로 발행하거나 수정한 결과를 확인할 수 있다.

### 포함하지 않는 범위

- 관리자 앱 배포
- 다중 사용자와 역할별 관리자 계정
- 분석 지표 화면
- 사용자 확인 전 이미지 저장소 추가

## B-04 비식별 지표 저장·집계

### 목표

정의된 행동 이벤트만 개인정보 없이 저장하고 포트폴리오에서 근거로 제시할 수 있는 기간·글·탐색 지표를 로컬 관리자에서 확인한다.

### 태스크

- [ ] B-04-01 `docs/analytics-conventions.md`의 이벤트와 저장 스키마를 다시 대조한다.
- [ ] B-04-02 브라우저가 분석 테이블에 직접 쓰지 않는 검증·수집 경계를 설계한다.
- [ ] B-04-03 허용된 이벤트 이름과 속성만 저장하고 나머지는 거부한다.
- [ ] B-04-04 검색어 원문, 전체 외부 URL, 사용자·세션·기기 식별자와 자유 입력값이 저장되지 않는지 검증한다.
- [ ] B-04-05 원본 이벤트 90일 삭제와 비식별 일·글 집계 24개월 보존 작업을 구현한다.
- [ ] B-04-06 기간별 조회 수, 글 열람, 검색 사용, 주제 선택, 목록 확장, 출처 확인 지표를 정의한다.
- [ ] B-04-07 식별자가 없으므로 사용자 수나 개인 전환율로 표현하지 않는 집계 함수를 구현한다.
- [ ] B-04-08 로컬 관리자에 기간·글·행동 기준 지표 화면을 추가한다.
- [ ] B-04-09 포트폴리오에서 사용할 지표의 정의, 분모·분자, 한계를 공유 문서에 기록한다.

### 완료 조건

- 계약에 없는 이벤트와 속성은 저장되지 않는다.
- 개인 식별 정보와 검색어 원문이 DB에 존재하지 않는다.
- 원본과 집계 데이터의 보존 기간이 재현 가능한 작업으로 적용된다.
- 지표 화면의 수치가 검증용 SQL 결과와 일치한다.
- SEO/GEO 성과는 내부 이벤트와 구분하고 Search Console 원본 지표가 있을 때만 설명한다.

### 포함하지 않는 범위

- 광고 식별과 사용자 프로파일링
- 개인·세션 단위 행동 추적
- 근거 없는 AI 인용률 추정

## Q-01 운영 전 통합 검증

### 목표

배포 전에 공개 앱, 로컬 관리자, Supabase, 분석, 접근성, SEO/GEO와 복구 절차가 함께 동작한다는 근거를 남긴다.

### 태스크

- [ ] Q-01-01 공개 역할과 관리자 역할의 RLS 허용·차단 시나리오를 다시 실행한다.
- [ ] Q-01-02 초안 작성부터 발행, 공개 조회, 수정 반영까지 전체 흐름을 검증한다.
- [ ] Q-01-03 홈, 검색, 글 목록, 상세, 소개, RSS, sitemap, robots를 데스크톱과 모바일에서 확인한다.
- [ ] Q-01-04 키보드 탐색, 포커스, 입력 이름, 명도 대비와 주요 접근성 오류를 확인한다.
- [ ] Q-01-05 canonical, Open Graph, JSON-LD와 공개 화면 정보의 일치를 확인한다.
- [ ] Q-01-06 공개 번들, 환경 변수, 저장소 이력에서 관리자 키 노출 여부를 검사한다.
- [ ] Q-01-07 DB 백업과 복구, 마이그레이션 실패 시 되돌리기 절차를 검증한다.
- [ ] Q-01-08 남은 위험과 수동 확인 항목을 `docs/production-readiness.md`에 기록한다.

### 완료 조건

- 차단돼야 하는 DB 접근이 모두 실패한다.
- 주요 사용자 흐름과 공개 빌드가 통과한다.
- 실제 화면과 검색·공유 메타데이터가 일치한다.
- 백업, 복구, 롤백 절차를 다른 환경에서 재현할 수 있다.
- 배포를 막는 미해결 항목이 없다.

## D-01 `develop → main` 병합과 Vercel 공개 배포

### 목표

통합 검증을 통과한 공개 블로그만 `main`에 병합하고 Vercel에 배포한 뒤 운영 주소에서 다시 확인한다.

### 태스크

- [ ] D-01-01 Q-01 문서에서 배포 차단 항목이 없는지 확인한다.
- [ ] D-01-02 Vercel의 루트·빌드 명령·환경 변수가 `apps/web` 공개 앱만 대상으로 하는지 확인한다.
- [ ] D-01-03 운영 Supabase에는 공개 읽기용 값만 제공하고 관리자 키가 없는지 확인한다.
- [ ] D-01-04 `develop → main` PR에 전체 검증 근거와 롤백 방법을 기록한다.
- [ ] D-01-05 사용자 최종 확인 뒤 PR을 병합하고 Vercel 배포를 실행한다.
- [ ] D-01-06 운영 주소의 홈, 글, 404, robots, sitemap, RSS, canonical과 공유 미리보기를 확인한다.
- [ ] D-01-07 Search Console 소유권, sitemap 제출과 색인 관찰 기준을 설정한다.
- [ ] D-01-08 배포 버전과 운영 확인 결과를 `docs/production-readiness.md`에 추가한다.

### 완료 조건

- 관리자 경로, 코드, 환경 변수와 쓰기 권한이 배포 결과에 없다.
- 운영 공개 글과 SEO/GEO 표면이 Supabase 발행 데이터와 일치한다.
- 배포 실패와 데이터 문제의 롤백 경로가 문서화돼 있다.
- Search Console에서 색인과 검색 노출을 관찰할 준비가 돼 있다.

결정이 필요한 시점이 오면 구현 전에 선택지와 영향 범위를 사용자에게 보고하고 확인받는다.
