# SEO·GEO 콘텐츠와 구현 기준

## 목적

`여백의 노트`는 검색 결과와 AI 기반 검색·요약에서 모두 신뢰할 수 있는 출처가 되는 것을 목표로 한다. 목표는 노출 그 자체가 아니라, 독자가 출처와 맥락을 확인할 수 있는 유용한 기록을 축적하는 것이다.

## 글 단위 필수 정보

발행 전 아래 정보를 콘텐츠 모델에 갖춘다.

| 항목 | 기준 |
| --- | --- |
| 제목 | 글의 질문·주제를 구체적으로 설명한다. 과장하거나 낚시성 표현을 쓰지 않는다. |
| 요약 | 본문과 일치하는 1~2문장으로, 글이 다루는 대상과 결론 또는 범위를 밝힌다. |
| URL | 발행 뒤 바꾸지 않는 `slug`를 사용한다. |
| 날짜 | `datePublished`와 `dateModified`를 분리해 관리하고 본문 가까이에 표시한다. |
| 분류 | 분야 1개를 반드시 고른다. 태그는 검색·연결에 실제로 도움이 될 때만 추가한다. |
| 출처 | 사실·수치·인용에는 원문 링크, 발행처, 확인 날짜를 남긴다. |
| 작성 주체 | 브랜드명 `여백의 노트`로 일관되게 표시한다. 개인 신원 공개는 요구하지 않는다. |

## 주제별 보강 기준

| 글 유형 | 추가로 보여 줄 맥락 |
| --- | --- |
| 경제·시사 | 자료의 기준 시점, 출처, 해석과 사실의 구분, 정보 제공 목적 |
| 제품 리뷰 | 정확한 제품명·모델, 사용 또는 비교 조건, 검토 날짜, 참고 자료 |
| 개발·학습 | 적용한 버전·환경, 재현 가능한 단계, 공식 문서 또는 원 출처 |
| 생각·에세이 | 개인 의견임을 분명히 하고, 외부 사실을 인용하면 출처를 연결 |

## 공개 웹 구현 기준

공개 Next.js 앱으로 전환할 때 아래를 구현한다. 현재 Vite 프로토타입에 억지로 부분 적용하지 않는다.

- 글마다 고유한 title, meta description, canonical URL, Open Graph 정보를 렌더링한다.
- 발행 글에 한해 실제 본문과 일치하는 `BlogPosting` 또는 `Article` JSON-LD를 제공한다. 제목, 요약, 대표 이미지가 없으면 구조화 데이터에 빈 값을 넣지 않는다.
- 홈에는 브랜드명 `여백의 노트`를 반영한 `WebSite` 구조화 데이터를 제공한다.
- 발행 글만 포함한 sitemap과 RSS를 생성하고, robots 정책·canonical과 일치시킨다.
- 공개 글·목록·소개는 정적 생성 또는 서버 렌더링으로 제공해 크롤러와 공유 미리보기가 동일한 핵심 정보를 받게 한다.
- 구조화 데이터는 배포 전 Rich Results Test로, 배포 후 Search Console로 검증한다.

## 금지하는 GEO 방식

- AI가 읽기 쉽다는 이유만으로 같은 내용을 문단·페이지·FAQ로 반복하지 않는다.
- 사용자에게 보이지 않는 텍스트·링크·메타데이터를 넣지 않는다.
- 출처 없이 AI가 만든 요약·수치·후기를 사실처럼 발행하지 않는다.
- 효과가 검증되지 않은 AI 전용 파일이나 마크업을 기본 요구사항으로 추가하지 않는다.

## 지표와 검토

- Search Console에서 색인, 검색 노출, 클릭, 검색어를 관찰한다. AI 검색 기능 데이터가 제공되는 경우에는 해당 원본 보고서로 별도 확인한다.
- 분석 이벤트는 `post_opened`, `search_used`, `filter_applied`처럼 사용자 행동만 수집한다. 검색어를 저장해야 한다면 개인 식별·민감 정보가 섞이지 않도록 별도 보존 정책을 정한 뒤 진행한다.
- SEO/GEO 변경 PR에는 수정한 표면, 구조화 데이터·메타데이터 검증 결과, 색인 영향, 롤백 방법을 남긴다.
